# PocketLocket — Handoff / Onboarding

A practical guide to pick this project back up on another Mac. It's a private,
**on-device, backend-free** iOS budgeting app (SwiftUI + SwiftData + Swift Charts).

Last verified: Xcode 26.6, macOS 26.x, iOS 26 simulator. 54 Swift files, **40 tests passing**.

---

## 1. Move it to the new machine

There is **no git repo yet**. Two options:

- **Copy the folder** `~/Documents/Budget_App` to the new Mac. You can skip
  `**/DerivedData/` and `**/.build/` (regenerated). Keep `tools/` — it contains a
  prebuilt XcodeGen so you don't need Homebrew/sudo.
- **Or start version control** (recommended): from the repo root run
  `git init && git add . && git commit -m "snapshot"`. The [.gitignore](../.gitignore)
  already excludes the generated `.xcodeproj`, DerivedData, `tools/`, and secrets.

> The Xcode project (`ios/PocketLocket.xcodeproj`) is **generated by XcodeGen** and is
> git-ignored. Always regenerate it after cloning/copying (step 3).

---

## 2. Prerequisites

- macOS with **Xcode 26.x** (built/tested on 26.6). Set it active:
  `sudo xcode-select -s /Applications/Xcode.app`
- **No accounts required.** The app is fully local — no Plaid, no Supabase, no
  server. (Optional at runtime: a SimpleFIN Bridge subscription ~$15/yr for
  auto-sync; file import and manual entry are free.)
- An iOS simulator runtime (Xcode installs one; the app targets **iOS 17+**).

---

## 3. First-time setup & everyday commands

All commands from the **repo root** unless noted.

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
export PATH="$PWD/tools/xcodegen/bin:$PATH"     # prebuilt XcodeGen, no install

# Generate the Xcode project (run after any add/remove of source files)
( cd ios && xcodegen generate )

# Build
xcodebuild -project ios/PocketLocket.xcodeproj -scheme PocketLocket \
  -destination 'platform=iOS Simulator,name=iPhone 17' build

# Run all tests (40)
xcodebuild -project ios/PocketLocket.xcodeproj -scheme PocketLocket \
  -destination 'platform=iOS Simulator,name=iPhone 17' test
```

`scripts/bootstrap.sh` also installs tooling (Homebrew/XcodeGen) and generates the
project, but the prebuilt `tools/xcodegen` means you usually don't need it.

Open in Xcode: `open ios/PocketLocket.xcodeproj` → run on a simulator, **My Mac
(Designed for iPhone)** (Apple Silicon), or a device.

**⚠️ Golden rule:** adding or deleting a Swift file? Re-run `xcodegen generate`
before building — the project is regenerated from `ios/project.yml`, not hand-edited.

## 4. Signing

Configured in [ios/project.yml](../ios/project.yml):
- Bundle ID: `com.vratnakaram.PocketLocket`
- `DEVELOPMENT_TEAM: ABCDE12345` (automatic signing)

On a Mac signed into the **same Apple ID**, it just builds. On a different Apple
ID: in Xcode → Settings → Accounts add your Apple ID, then change `DEVELOPMENT_TEAM`
in `project.yml` (or pick your team in Signing & Capabilities) and, if the bundle
ID is taken, change the `bundleIdPrefix` in `project.yml`. Free Apple ID works
(7-day resign); the Apple Developer Program ($99/yr) is only for TestFlight /
1-year signing.

## 5. Architecture (how it fits together)

- **Local-first, no backend.** All data lives on-device in **SwiftData**; secrets
  in the **Keychain**. Nothing is sent to any server we run.
- **Data sources:** SimpleFIN Bridge (read-only, device→bridge over HTTPS),
  OFX/QFX/CSV **file import** (on-device), and **manual entry**.
- **Categorization** is computed live: user rules → merchant heuristics →
  provider category. `MerchantHeuristics.category` is memoized for performance.
- **On-device AI** (Save tab): Apple `FoundationModels` (iOS 26+), guarded with
  `#if canImport(FoundationModels)` + `if #available(iOS 26.0, *)`, cached by input
  signature. Degrades to the rules-based `SavingsAdvisor` when unavailable.
- **Security:** Face ID/passcode gate (`BiometricGate`), the SimpleFIN access URL
  is Keychain-stored **bound to biometrics** (`SecAccessControl(.userPresence)`),
  a privacy blur covers the app when backgrounded, and an encrypted **Backup &
  Transfer** (AES-GCM + PBKDF2) moves data between devices.

See [docs/ARCHITECTURE.md](ARCHITECTURE.md) for diagrams and detail.

## 7. What's built (feature inventory)

- **Home:** spend ring (Donut or Progress; Progress shows over-budget as a red
  second lap), Month/Year toggle with bounded navigation, category breakdown with
  per-category budget progress, **Safe to spend** (overall or starred-category
  focus), tap ring segment → category detail, tap year bar → that month.
- **Transactions:** search, filters (account/category/type/period), **sort**,
  recategorize (teaches a rule), **manual add/edit/delete** (swipe on manual rows).
- **Accounts:** net worth, per-account **include/exclude** toggle for spending,
  pull-to-refresh + Sync button.
- **Save:** rule-based + on-device AI insights (month-over-month trends, top
  merchant, biggest expense), **Subscriptions** tracker.
- **Settings:** monthly + **per-category budgets** (with ★ Safe-to-spend focus),
  **category rules** manager, connections, **encrypted Backup & Transfer**,
  reset local data.
- **Cross-cutting:** biometric lock, background privacy cover, Reduce Motion &
  Dynamic Type support, SimpleFIN/import **cross-source de-dup**.

## 8. Testing & verification

- 40 XCTests (pure logic + `ImageRenderer` snapshot tests). Run with the `test`
  command above.
- **Snapshot trick:** `PocketLocketTests/UISnapshotTests.swift` renders components to
  `/tmp/ring_*.png`. This is the way to visually verify UI, because the **biometric
  gate blocks normal simulator screenshots** when the sim has a passcode.
- Reseeding SimpleFIN demo data or clearing state: use **Settings → Reset local
  data**, or `xcrun simctl uninstall booted com.vratnakaram.PocketLocket`.

## 9. Gotchas & conventions

- **Regenerate after file changes** (`xcodegen generate`) — the `.xcodeproj` is generated.
- **No stored category** for synced/imported rows — it's resolved live. Manual rows
  store a canonical Plaid primary (`SpendCategory.plaidPrimary`) so the choice sticks.
- **SimpleFIN protocol notes:** amounts are strings; positive = money in, so the app
  negates on import; transaction ids repeat across accounts, so they're namespaced
  `sf-<accountId>-<txnId>`; a ~13-month window is fetched so history accumulates.
- **Persistence keys** (`@AppStorage`/UserDefaults): `monthlyBudget`, `ringStyle`,
  `excludedAccountIds`, `categoryBudgets`, `safeToSpendFocus`, `ai_insight_text`,
  `ai_insight_signature`.
- **Swift 5 language mode** (`SWIFT_VERSION=5.0`) to avoid strict-concurrency churn.
- SwiftData model additions are lightweight-migratable (give new fields defaults).
